# Disposable demonstration model

Baseline: u1 Lia Exemplo / lia@example.test / admin; u2 Caio Modelo / caio@example.test / regular; u3 Nina Teste / nina@example.test / regular. Fictional IDs/names, no real people. Avatars: up to two initials, generic icon for blank name. Status label “Exemplo” is not account activation.

State: users, actorId|null, nextId, route, feedback, listScenario, importScenario, saveOutcome, deleteOutcome, operationSequence and pending. saveOutcome/deleteOutcome each accept success|error and default to success. No storage. Restart/reload recreates identical baseline and login, including both success defaults. Sign-out clears identity but retains changes in that page lifetime. Counts derive from records/roles.

User drafts: trimmed name/email and role admin|regular; blank name/email or syntactically invalid email produces illustrative inline errors, not production validation policy. Signup always regular. Own-profile edit has no role control. Administrator can edit others; own role and last-admin deletion/demotion return “Decisão de produto pendente” without mutation. Regular actor may only edit/delete self, including forged action/hash attempts. Deleted own account leads to login with recoverable explanatory feedback.

List scenarios populated/loading/empty/error change presentation, never erase fixtures. Recovery or create restores populated. All confirmation, pending, cancel, retry, duplicate guards and import phase rules belong to pure state.mjs transitions, not the adapter. beginSave/beginDelete validates actor/target/draft or exact trimmed EXCLUIR, refuses a second operation while pending, increments operationSequence and snapshots operation ID/kind/target/draft/outcome. completeOperation accepts that ID only if it still matches pending, returning the chosen failure without mutation or committing once. cancelOperation clears pending; a late completion of that ID is a no-op even after a new operation starts. Route change/reset/sign-out dispatch cancellation. app.mjs only schedules/clears the400ms timer and dispatches its completion ID. Errors persist with retry via the same action. State transforms return a new state.

Deterministic failure injection: save forms have separate “Controles da demonstração” with “Resultado de salvar” selector (Sucesso/Falha ilustrativa). The deletion dialog has its own separate demonstration fieldset and “Resultado de excluir” selector so it remains reachable inside the modal. Select error and submit valid input → pending → persistent illustrative failure, unchanged records/counts. Select success and retry the same Save/Excluir action → one mutation. Changing outcome preserves draft/confirmation/target and never changes records; selectors are disabled while pending. Cancel during pending cancels its outcome; no delayed mutation follows. Reset restores success defaults. Core tests and native DOM tests cover these exact steps, repeated submit and late completion for both actions.

Within one loaded page, explicit restart preserves a monotonically increasing operationSequence even while resetting all visible baseline data, so a stale pre-restart completion cannot collide with a newly started operation. A full page reload destroys the previous execution context and starts a fresh sequence. Tests distinguish identical visible baseline from internal operation identity.

Import: supplied CSV or XLSX, filename pessoas-exemplo.csv|xlsx, phase idle/selected/queued/processing/completed/partial/failed and chosen outcome. Select → start → queued → explicit advance → processing → explicit advance → result. Retry→selected; replace chooses another sample. No file object, parsing, percentage, user insertion or counter change. Results are scenario text, not records processed.

Routes: visitor admin/deep routes fall back to login; regular admin routes fall back to own profile. Unknown route/missing record gives a clear message and role-appropriate destination. These are demo guards, not server authorization. Back/forward restores route, not unsaved form drafts; role identity persists within page lifetime only.
